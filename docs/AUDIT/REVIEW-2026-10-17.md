# Caesar CZR — Review 2026-10-17

Scope: caesar-czr-internal-real. Closed.

## Summary

Eight planned items reviewed; seven closed; three new
findings recorded. No consensus, wire, or storage format
changed.

## Closed findings

**E — P2P discovery/sync (802e273).** parse_peers_payload()
built P2PPeerEndpoint from untrusted bytes without calling
validate(); a hostile peer could inject non-IPv4 strings,
loopback (127.0.0.0/8), or multicast (>= 224.0.0.0) into
the discovery set. Fixed by constructing + validating each
endpoint. C6-2 / C6-6 / C5-7 documented (IPv4-only scope;
loopback rejected as confused-deputy mitigation; multicast
and the limited broadcast rejected).

**C8-1..C8-7 — relay quadratic cleanups (1180b66, 4990a7a).**
Four O(N*K) patterns in P2PRelay let one authenticated peer
burn minutes of CPU per request: per-block rebuild_utxo_set
in handle_blocks; nested hash loops in get_blocks /
get_sync_blocks / get_headers; invalidate_cache_callback_
read without its mutex; single-block framing overflow. All
fixed. Dead peer_loop removed.

**C3-2 — address case (5cf9a9d).** address_from_public_key
hashed the key text, so "ABC..." and "abc..." derived
different addresses. Added canonicalize_public_key() that
lowercases A-F only. Regression test added.

**C4-2 — OpenSSL (54a1ec1).** auth_google.cpp used
SHA256_CTX / SHA256_Init / SHA256_Update / SHA256_Final
(deprecated in OpenSSL 3.0). Replaced with caesar::sha256().
Bit-for-bit output unchanged.

**C6-5 + R1 — node mempool and traces (16a32ea, 7a654e6).**
submit_pool_solution wrote ~20 std::cerr lines per call;
replaced by CZR_NODE_TRACE (disabled by default).
submit_transaction (called by HTTP RPC at http_rpc.hpp:2593
and :13202) duplicated admission without calling
relay_.announce_transaction(); transactions submitted via
RPC never propagated to peers. Fixed: one-line alias to
accept_transaction().

  Methodological note: the first C6-5 commit also replaced
  std::cerr inside the macro definition, yielding a self-
  referential macro that would fail only when enabled. It
  compiled only because the disabled branch was taken.
  Caught by a second build with -DCZR_NODE_TRACE_ENABLED
  and fixed in 7a654e6. Rule adopted: any commit that adds
  or modifies a compile-time macro must include a build of
  the affected target in both configurations.

**C7-2-test — slowloris regression (9a68eea).** eadd460
bounded the handshake by an absolute deadline but nothing
in tests/ exercised it. New test opens a raw TCP socket,
sends one byte of the 4-byte length prefix, stops, and
asserts the server closes in [1s, 8s]. Observed: 5.22s.
CTest timeout 30s.

## Deferred (needs sign-off)

**C1-3 / C2-4 — pool operator fee cap.** http_rpc.hpp:153
(g_pool_fee_percent = 35.0) read at :415 via std::stod(val)
with no bound; >100 underflows worker_pool on uint64_t.
Recommended: CZR_POOL_FEE_PERCENT_MAX = 50.0, validate at
config load, document that operator fee is UI-layer not
consensus. Product decision.

**C5-2 — difficulty freeze.** consensus.hpp:182-183 freezes
on (a) current > CZR_MAX_DIFFICULTY — an undocumented
protocol assumption — and (b) window-size mismatch — silent,
no test coverage. Recommended: keep the ceiling, document
the assumption, split the two conditions, treat window
mismatch as an unexpected state. Protocol decision.

## New findings (for follow-up, not fixed)

- S1 high: auth_google.cpp does not verify the id_token
  signature against Google's JWKS. Any id_token string with
  an arbitrary email claim is accepted.
- S2 low/med: derive_wallet() emits a 43-char address;
  is_valid_address() requires 75. Demo-only today; would
  break if used as a real recipient.
- S3 med: https_post() shells out to curl via popen(); no
  subprocess timeout, no fallback if curl is missing.
- R7 med: mine_one_block() and submit_pool_solution() call
  mempool_.clear() while replace_chain() calls
  revalidate_mempool_after_reorg(). Mining drops valid
  pending fees; reorg does not.
- M1/M2 low: node.hpp start() calls chain.front()/back()
  after storage_.load() with no empty check.
- M3 low: stop() noexcept calls join(); join() can throw
  std::system_error, which would terminate.
- M4 low: stop() releases lifecycle_mutex_ before calling
  server_.stop(); a concurrent start() can race.
